> 给**人**看的（AI 协作者看 `AGENTS.md`）。
> 读完这一篇，你应该能在一个小时内交出自己的第一个改动。

---

## 0. 先搞清楚你适合哪一档

| 档位 | 要会什么 | 要装什么 | 典型产出 | 门槛 |
|---|---|---|---|---|
| **A. 报问题** | 会用浏览器 + 写几句话 | 什么都不用 | 「这题答案错了」「这页图糊了」 | 5 分钟 |
| **B. 补内容** | 会编辑 JSON / Markdown | Python 3（只为跑检查） | 写题解、补题目、校对笔记 | 半小时 |
| **C. 改代码** | 会 HTML/JS 或 Python | Python 3 + Node（可选） | 新功能、修前端 bug | 半天 |

**别小看 A 档。** 这个项目最贵的东西是「校对过的内容」，
而校对只能靠看得懂 DSE 生物的人肉眼找。你发现一处错误，价值高于写十道新题。

## 1. 五分钟跑起来

```bash
git clone https://github.com/nzgjsmy/ShenZhiHe.git
cd ShenZhiHe
git checkout source          # ★ 必须。main 只有部署产物，源码在 source
python site/build.py         # 生成单文件网站
```

构建完会得到 `site/神智核.html`（约 3.7 MB）。**直接双击打开就能用**，
不用装服务器、不用 npm install——`build.py` 只用 Python 标准库，零第三方依赖。

想更接近线上环境（service worker、相对路径都正常）：

```bash
cd site && python -m http.server 8080
# 浏览器打开 http://localhost:8080/神智核.html
```

提交前跑这三条，**全绿才算完成**：

```bash
python site/build.py
python scripts/verify_build.py     # 构建产物自检（11 项）
python scripts/guard_data.py       # 题库守门员：确认没改到不该改的字段
python scripts/check_quiz.py       # 测验题自检（只有你动过 quiz/ 才需要）
```

```
│   ├─ bio/bio02.json …         ← 959 题
│   ├─ chem/                    ← 623 题
│   └─ phys/                    ← 946 题
├─ extras/                      ← 「额外资讯」里的附件（公式表等）
├─ site/

│   └─ 神智核.html              ← 产物，别手改
└─ scripts/                     ← 检查工具
```

### 三种 JSON 长什么样

**① 笔记知识点**（`data/bio/bio02.json`）

```jsonc
{
  "id": "bio02",
  "title": "生命的基本單位",
  "sections": [
    { "id": "bio02-s1", "title": "細胞學說與顯微鏡",
      "points": [
        { "id": "bio02-s1-p1", "title": "細胞學說的三條主張",
          "page": 1, "tags": ["細胞學說"],
          "body": "markdown 正文，图片写成 ![说明](img/bio02_p01.webp)" }
      ] }
  ]
}
```

**② 课题测验题**（`quiz/bio/bio02.json`）—— 完整示例见 `docs/examples/quiz-example.json`

```jsonc
{
  "topic": "bio02",
  "questions": [
    { "id": "bio02-q1", "type": "mc", "point": "bio02-s1-p1",
      "q": "下列哪一項屬於化合物？",
      "options": ["氧氣", "食鹽", "碳", "氮氣"],
      "answer": 1,                    // ← 索引，0=A 1=B 2=C 3=D，不是字母！
      "explanation": "化合物由兩種或以上元素…" }
  ]
}
```

`type` 有三种：`mc`（四选一，`answer` 是 0–3 的整数）、`tf`（对错，`answer` 是 true/false）、
`fill`（填空，`answer` 是非空字符串数组）。`point` 必须指向**真实存在**的知识点 id，
否则学生点题目跳不过去。

**③ DSE 真题**（`data/bio/_pastpaper.json`）

```jsonc
{
  "id": "_pastpaper", "title": "DSE 生物歷屆真題（卷一 MC）",
  "years": {
    "2012": [
      { "id": "pp_2012_q1", "year": "2012", "qnum": 1, "pct": 73,
        "topic": "bio08",
        "q": "以下哪種組織類別具有最多線粒體？",
        "options": [ { "k": "A", "v": "氣囊壁" }, … ],
        "answer": "D",                 // ← 这里是字母，和测验题不同
        "explanation": "",             // ← 只有这个字段允许你填
        "explSource": "notes",
        "img": "img/pp/2012/f1.webp" }
    ]
  }
}
```

> ⚠️ **这个文件里只有 `explanation` 和 `explSource` 可以改。**
> `q`/`options`/`answer`/`topic`/`pct`/`img` 全部人工逐题校对过，
> 脚本或「顺手优化」一旦改动，错误会静默上线且极难追溯。
> 确有 bug 要修，见 §6。

### ② 化学、物理没有真题库 ⭐ 最大的一块空白

目前只有生物有 `_pastpaper.json`。化学和物理的 DSE 卷一 MC 完全可以照同样的结构做一份
（`data/chem/_pastpaper.json`、`data/phys/_pastpaper.json`）。

- 数据格式直接抄生物的，`topic` 换成 chem/phys 的课题 id
- 需要：原卷 PDF（扫描版也行，本项目已有 OCR 流程）、各年《评卷参考》的答案与答对率
- 前端 `viewPastPaper()` 是通用的，只要数据进去就能显示，**不用改代码**
- 工作量不小，建议一个科目一个人，做完再合并

### ③ 缺 22 道真题

## 4. 怎么提交

### 用 Pull Request（推荐给外部协作者）

```bash
git checkout source
git pull                                  # 先拉最新，避免基于旧版改
git checkout -b fix/bio25-explanations    # 分支名：<类型>/<范围>
# …改文件…
python site/build.py && python scripts/verify_build.py && python scripts/guard_data.py
git add -A && git commit -m "bio25：补 29 题题解"
git push -u origin fix/bio25-explanations
```

然后在 GitHub 上开 PR，目标分支选 **`source`**（不是 main）。
CI 会自动跑构建 + 自检，全绿才能合并。

### 直接推（只给信任的人）

```bash
git checkout source && git pull
# …改文件 + 跑检查…
git add -A && git commit -m "说明" && git push origin source
```

### commit 信息怎么写

```
<范围>：<做了什么>

bio25：补 29 题题解
chem：新增 2012–2022 真题库（12 年，412 题）
fix：pp_2019_q34 选项吞并了后 11 题（48 → 4）
docs：贡献指南
```

**别写**「update」「修改」「fix bug」——半年后没人知道那是什么。

## 5. 怎么避免打架

1. **开工前先 `git pull`**，并在 `SHARED-MEMORY.md` §3「占用状态」登记一行：
   `bio25 题解 — 你的名字 — 2026-10-26`
2. **按课题/文件切分**：你改 `bio25`，别人改 `bio08`，物理上不可能冲突
3. **不要两个人同时改 `site/template.html`**——这是唯一的共享热点，
   要改先协商，或者一次只一个人改
4. **详细过程写进自己的日志**：`docs/journal/<日期>-<你的名字>.md`，
   `SHARED-MEMORY.md` §5 只留一行摘要（那个文件所有人都要读，写长了没人看）

## 6. 红线（违反会直接出事）

| 别做 | 后果 |
|---|---|
| 手改 `site/神智核.html` | 下次构建全被覆盖，白干 |
| 用 `site/build.mjs` 构建 | 真题页整页空白（缺 `_pastpaper`） |
| 设 `EMBED_IMG=1` | HTML 从 3.7 MB 涨到 63 MB，线上直接崩 |
| 改 `_pastpaper.json` 的受保护字段 | 校对过的内容被破坏，错误静默上线 |
| 部署时只复制 `index.html` | 新增图片全 404（已发生两次） |
| 改版不 bump `site/version.json` | 客户端吃旧缓存，用户看不到更新 |

**确需修受保护字段**（例如某题选项吞并了邻题）时，用白名单显式声明，并在 commit 里写原因：

```bash
python scripts/guard_data.py --allow pp_2019_q34:options
git commit -m "fix：pp_2019_q34 选项吞并后 11 题（48→4），已核对原卷"
```

## 7. 让 AI 帮你做

如果你用 WorkBuddy / DeepSeek Harness / Claude Code 之类的工具，**开头先说这句**：

> 读一下这个仓库的 `AGENTS.md` 和 `SHARED-MEMORY.md`，然后按里面的规矩来。

这两个文件就是为 AI 写的：`AGENTS.md` 是硬约束（哪些操作会导致线上故障），
`SHARED-MEMORY.md` 是现状与历史坑。AI 读完就不会重蹈覆辙。

给 AI 派活时把范围说死，例如：

> 只改 `data/bio/_pastpaper.json` 里 topic 为 `bio25` 的题的 `explanation` 字段，
> 其余字段一律不动。写完跑 `python scripts/guard_data.py` 确认无错误。

## 8. 卡住了怎么办

1. `python scripts/verify_build.py` 报什么，先照着提示修
2. 看 `SHARED-MEMORY.md` §4「已知陷阱」——90% 的坑都记在那里
3. 页面白屏/按钮没反应：先按 F12 看 Console，多半是某个渲染函数抛异常
4. 还不行就开个 Issue，把**报错原文 + 你跑了什么命令**贴上去
